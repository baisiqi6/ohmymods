# Palace layout visual consumers, first slice

Run `python3 run.py --output <outside-product-tree> --dotnet <SDK-dotnet> --registry <reviewed-actor-batch1/registry.json>`.

The four suites compile actual production files. Geometry and actor registry are pure readers/math. NativeBinding and ArrivalPlacement are compiled whole against explicit host surfaces; these tests prove adapter decisions and position write counts, not Unity collider behavior, Harmony ordering, active W authority or a native trip.

- Geometry keeps the old three-argument 1448/645/187 behavior and the old rear envelope. Explicit Capital400 descriptors use the reviewed authored street reference224 in tests. This is design input, not complete art/native readiness.
- Binding refuses Capital400 through the old overload, verifies current whole-island view identity and exactly three physical probes, and keeps the legacy48 span route without inventing a whole-island recipe.
- Arrival tests missing layout, current layout/key/owner drift, cold ±199, typed sailing/boat/newReign gates, one-trip budget, old44 gate, v2 return and explicit same-key v4 source-anchor return.
- Actor parsing consumes the real SHA-pinned 10-atlas/294-timed-frame registry. Dancer's26 timed frames use21 explicit physical rectangles; rectangles may repeat with separate durations. Image bytes are not opened here. Atlas/frame pixel hashes were independently read back by Root; this reader only validates their declared syntax and coordinates.

No test writes game data, deploys a plugin, loads textures, promotes resources or creates a full scene. All `.cs.txt` files are test inputs and stay outside the main project's C# wildcard.
