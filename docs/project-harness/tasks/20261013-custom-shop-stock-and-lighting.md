# Issue 225：自定义商店库存迁址与原生照明（候选）

目标：[Issue #225](https://github.com/baisiqi6/ohmymods/issues/225)。基线为 PR #224 合并提交 `100c181e91a6edf0dc673fb94645e40b4b20f2c0`，IL2CPP 2.4.0。玩家确认遗留火枪现象发生于该次更新之前，不能据此判定 #224 回归。原事件的具体 Clear 触发原因尚未从实机复现。

## 改动

- 火铳铺与盾具店在既有占地实际越出完好城墙边界时撤收；边界仍覆盖店铺时保持原位。检查为既有 Tick 内每 0.5 秒常量读取，不增加全场工具或单位扫描。重新选址继续使用既有原生排除规则。
- 有界库存控制器只接管精确证明的已付、未领取、未认领工具。保留原生对象、paid GUID/receipt、库存槽和持久化资格；不增发武器、付费记录或旧档补偿。撤收间隙分别借用双方拾取策略及自有视觉旗标，新架落位后逐字段恢复；外部接管、对象复用、异常和终止路径分别处理。
- 已被友军或敌人认领、已拾取以及掉落后不再属于货架的物品不回收。暂停保留同世界店体或待重建责任；关闭、失去单机权限、世界更换、失败撤收及驱动销毁执行清理。身份撤销前恢复仍属自己的临时字段。
- 盾具视觉允许同一付费工具跟随新的货架位置，保留首次借用快照；同一位置的重复维护不会持续覆盖工具位置。
- 四种自定义商店使用独立原生 Torch/OilLamp/Torch_Bamboo donor；在未激活的自有根下初始化，使用原生环境亮度判断，采样至多每 0.25 秒一次。原生 Fire/AutoLightRegister 负责灯光注册，补丁不直接操作 LightFaker 注册表。灯根相对店面归零，最终视觉侧位尚待实机判断。

## 续测与竹林修正（2026-10-13）

两轮 Mac ARM64 隔离试验使用诊断候选 `c56584f1`，没有覆盖正常 DLL。首轮无新址时同一已付火枪原生对象行、身份及 slot 0 被保存；第二进程真实冷读准确绑定原来的两条付费记录，Loading 阶段已观察到库存火枪的双方拾取策略为 5，工具仍活动且可持久化。解除私有无址 fixture 后生产 Create 路径执行，但该测试进度没有完整外墙，未出现新架，重新上架和真实领取仍未触发。现有观察点不能证明首次 AI 资格检查前的完整排序。

Courier 的 OilLamp 首轮稳定唯一注册，续轮观察到亮灯根关闭；旧探针未按原 pointer 追踪注销，因此不能据此判定清理成功，也不能外推其他三店、竹林或白天暗处。四店与自然破门等剩余门保持开放。

先前“BambooLamp 自查环境即可保证白天暗处照明”的推断被当前 2.4 资源与 ARM64 实现证据推翻：Torch_Bamboo 的 AutoLightRegister 含夜间专用标志，OnEnable/Start 仍可能关闭实际 Light.enabled；BambooLamp 只控制光晕和子根，不能消除该额外写者。修正要求自有未激活克隆恰有一个既存注册器，在首次激活前设置 nightLightOnly=false 并读回；数量异常、写入失败或无效果均沿原 Abort 清理。不添加组件、不直接写 Light.enabled，Fire/OilLamp 路径保持。

该修正有真实源链接 RED→GREEN 回归，完整适配套件由 334 增至 372 assertions；Root 与独立审查复跑通过，当前 interop 的公开 .NET 8 构建为 0 警告、0 错误，GLM 5.3/max 批准源码与 Draft 交付。实际 Bamboo 日间暗场和原生注册生命周期尚待修正后的候选验收，不能引用旧 `c56584f1` 的希腊结果代替。

两轮均恢复各轮启动前的新鲜原件。首轮因退出后唯一设置时间戳晚写而触发严格比较失败，保留失败证据后经精确恢复。续轮在归档前的有界观察中记录了一次同键晚写，再执行未放宽的归档比较、原件恢复及恢复后 30 秒严格五通道核对；全部通过。晚写者未归因，没有改正常设置或放宽恢复条件。私人存档、身份、原生日志与测试控制脚本仅保留本机。
