# 伤害结算与开销只读审查

日期2026-09-17；当前本机0b1ad4e1（快速购买弹药），伤害代码与公开9.0.0相同。本轮仅审查，不改生产代码、安装包或用户数据，不新增日志/Hook，不运行游戏或性能基准。

## 确认的行为与风险

- 火枪在 `MusketeerCombat.cs:338` 拒绝死亡/无效Damageable；`Tick`在765–772先移除本颗子弹，再调用原生ReceiveDamage(2)。未发现单颗弹重复推进反复结算的路径。护盾/无敌仍由原生伤害入口处理，调用2点不等于实际HP必减2。
- 火枪每颗活弹每帧做一次LinecastNonAlloc（962），只查Enemies层；按需32→64→128→256扩容并复用，但饱和时可能同段多次查询。结果达到256上限仍饱和或物理API异常时，该弹无伤害终止（917–923、947–980）。这是明确的保护性放弃，不是已观察到的普遍漏伤。4096活弹表满会跳过新射击（705–716）。未知敌人类型/Boss被保守目标白名单排除，属于当前职业支持范围，不能误称已经支持全部地面Boss。
- 每发仍new一个小的托管MusketeerBullet（1046）；视觉GameObject池在冷启动/齐射新高峰时增长（1090–1110），不是绝对零分配。稳态缓冲和视觉对象复用；不能仅凭NonAlloc名称推断完全没有GC或原生互操作开销。
- 单帧推进delta上限.1秒（736），Age也按截断后的delta增加。持续低于10FPS时弹道相对墙钟时间会变慢；这是当前步长保护的可计算后果，未证明它导致了本次用户实际漏伤。没有真实帧时间测量。
- 条件性P2：GreekImpact同volley的受伤目标账本只存Damageable.Pointer，不包含敌人的新生命代次。同一对象在仍有该齐射箭在途时回池再生，会可能被旧目标记录误去重；代码条件确认，2.4实机发生率未知。不能把正常“同齐射范围伤害仅一次”的规则当bug，也不应粗暴取消去重改变平衡。详见arrow-review.md。
- 范围伤害Overlap查询64碰撞体、单齐射最多32目标属于现有上限。每次命中有界，但没有所有命中共享的每帧查询额度。不是逐帧全场扫描，也不代表总开销不随命中数量增长。
- 火焰视觉上限16个效果×3层×36顶点=1728顶点；每帧最多3456次PerlinNoise、3456次Round及48次顶点上传/Bounds重算。属于值得优先测量/优化的路径，未测耗时，不能宣称它是已确认卡顿根因。视觉上限不等于伤害查询预算。

## 死亡后命中

视觉上剩余箭弹仍在飞行并不等于再次扣血。模组火枪当前主动排除dead目标，AoE也校验活目标。2.1参考Damageable.ReceiveDamage在普通HP=0时跳过OnReceiveDamage，isDead阻止重复OnDeath，但OnPreReceiveDamage在更早位置调用；因此不能泛化成死后重复调用绝对无副作用。未核定2.4重复掉钱，未将其宣称成已发生的问题。

建议优先补目标生命代次去重边界，再测/优化火焰网格与碰撞查询的峰值；保留原有伤害规则及单齐射限伤。当前报告不是修复交付，也不是实机性能验收。
