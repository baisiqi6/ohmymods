# staggered-volley-024 — 夜战齐射错峰（性能优化）设计草案

> 状态：待性能数据；探针已部署（夜战窗口门控版）等用户守一夜血月。
> 排序：随时可插队做（小任务），数据到位即决策。

## 背景

- 骑士小队 rank 压缩（V2.1）把所有侍从弓箭手拉进射程 → 齐射规模可超原生峰值数倍。
- 每支箭 = Rigidbody2D + 碰撞触发 + **TrailRenderer**（最贵的逐对象渲染组件）。
- 原生射击冷却无随机抖动 → 怪潮同时进射程时全队列齐射同步 → 箭矢脉冲尖峰。

## 关键约束（用户定稿）

- **只针对夜间守城**：白天打猎/出击/拆传送门完全不动。
- 探针已按此门控（游戏时间 ≥17.5h 或 ≤5.5h 才采样报告）。

## 数据与决策

守一夜血月后看 `[DefensePerf] arrows=N avgFrame=X maxFrame=Y`：

| 数据形态 | 结论 | 方案 |
|---|---|---|
| maxFrame 高、avg 正常（尖峰型） | 齐射同步是主因 | 随机抖动：射击冷却 ±15-20%（无状态、几行代码） |
| avg 也持续高（持续型） | 扫描+射击的持续成本是主因 | **用户方案：每秒 5 批分片**——弓箭手按编号 %5 分批，
  每批在自己的 200ms 时间片内做扫描+射击决策（从每帧 N 次决策收敛为每秒 N 次且摊开） |

注意：抖动方案只对"已同步"的队列有效，新怪潮首轮仍会齐射；分片方案连首轮也错开。

## 实现挂点备忘

- 射击冷却写入处：Archer 的 `_cooldown = shootCooldownTime/WithKnightTime`（2.1.0 源码 1045 行区；
  2.4.0 行号可能漂移，按方法名定位）。
- 批次分配：弓箭手 instanceID % 5 或转职序号 %5（确定性，联机两端收敛）。
- 门控：`director.currentTime` 夜战窗口（探针 IsNightWindow 同款）。

## 已知坑（勿重踩）

- **Director.Update 在 2.4.0 钩不住**（AOT 内联）——性能探针最初挂在它上面从未出过数据；
  一切每帧/定时逻辑挂 World.OnLevelLoaded 协程宿主（PatchWorld_DefenseSpacing 先例）。
- FindObjectsOfType<Archer> 在 interop 下工作正常（实测 89 命中）。
