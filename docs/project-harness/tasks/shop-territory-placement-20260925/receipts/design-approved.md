## 复审结论：APPROVE（附3条非阻塞实现注记）

### 必改1撤回成立
我的反例针对“超集区间做 union 后从领地减去、在剩余段内取点”的构造——那里可忽略对象会**删掉**候选段。你们的契约是纯加法：阈值只**细分** cell，被超集区间覆盖的 cell 仍出内部中点候选。完整性论证成立：任一物理无遮挡极大缝 (a,b) 的边界必为真实 blocker/payable 的展开端点或领地端点，全部 ∈ 阈值集 ⊇ 真实阈值集；含缝中点的 cell 被 [a,b] 夹住，其中点严格落在 (a,b) 内、原生门必过。可忽略巨型区间只多切几刀，唯一窄缝的 cell 中点照常被测。我此前 tier-2(0.25步长) 是带缝宽下限的补丁，本方案零缝宽下限，严格更优。无真正反例。

### 必改2被更优方案取代
固定 ε=0.01 确实会删掉合法的 <0.01 窄缝；double 精确边界 + float 化后 `BitIncrement/BitDecrement` 找内部可表示值 + 原生闭区间触碰终检，三者组合既不删缝也不放过相触。领地恰店宽时中点由原生 fits 裁决，与旧 `exact fit` 语义一致。残余风险仅剩“double 展开端点与原生 float 计算的 p−d 差 ≤1 ulp”——量级 ~1e-5 世界单位（1/3000 像素），非物理可玩缝，原生终检权威，接受。

### 核对无异的其余点
- 候选量 O(对象数)（阈值 ≤2·(payables+blockers)+2），与领地长度无关；middle 快路径、5秒重试、已建店不扫、不改 native 集合、采集异常走既有失败路径不误判“全占”——全部正确。真实 blocker 采集失败选“整轮失败重试”而非逐条跳过是对的（跳过真 blocker 会丢该缝的界定阈值，破坏覆盖论证）。
- 双店互斥经 AllPayables 语义不变；纯 core + 共用 adapter + 两调用点 + 文案，scope 与前轮一致。

### 3条非阻塞注记（实现时落实）
1. **非 finite 区间过滤**：NaN/±Inf 的 exclusion 值须在采集处显式剔除或整轮失败——NaN 进排序不是异常，会静默乱序/丢 cell，绕过你们的失败路径。补一条测试。
2. **退化 cell 规则写死**：去重后 `t_{k+1} <= t_k` 的 cell 不产候选（零宽开缝本无可放点）；测试已有退化用例，断言落到这条规则上。
3. **旧钉扎删除**：tests/hero-shop 里 `calls==81`、`x==3`、`inside borders` 循环语义是 81 采样实现的行为钉扎，按新契约重写删除，不迁移复钉。ModConfig“领地中段”帮助文案仍留本轮外。

条件满足即无保留：APPROVE。
