# 跨风格随从补员排查与旧诊断清理
用户报告Greek之外风格随从死亡不补充，补充确认白天回城、附近有弓手也不补；担心旧探针引起卡顿。

实物2.4静态证明Knight.Update仍每10秒缺员时调用Fetch、10格范围，无风格分支；资格/保留空闲数/距离与Norse替换分别是不同环节。现有9/9日志481行中280行为旧弩箭诊断（146次无节流命中、134射击），无Error。相同9/9存档只读统计22knights各4所属Archer、141archers，不能代表用户后来观察的实时异常。无足够证据直接改补员规则。

本轮实现范围：移除纯诊断CrossbowTowerDiag三hook；新增只读有界Fetch/IsAvailable/Archer.OnDisable事件采样，每风格30s/共享3s，进程最多30行，嵌套调用逐层保存/恢复上下文，不重入调用资格/Fetch/Assign。复用既有KnightStyle巡检已取的单位数组做最多5次/120秒名册汇总，严格<=64knights+1024archers，不新增Find/Resources/Update/协程。名册差异注明缓存，不能自动清理或视为根因。包括异常总最多36诊断行。

诊断不改招募范围、保留弓手数、盾门、已有队籍、兵种、存档或用户设置。禁止杀死/替换单位以测试，不从其它小队/塔强拉兵。若需实战才确认的结果，保持doing并明确未完成根因修复。用户正常游玩后读取日志再实施对应修复。

ZCode优先worker；独立native scout/reviewer/tests；operator统一集成。只IL2CPP和E独立副本，游戏运行时不替换DLL；只受控启动验证，公开4.5包不修改，不commit/push/tag。保留既有Greek8/15、幕府回冲伤害、银行HUD/1204等未提交工作。

验收：实际API和原生地址唯一性，0W/0E编译，独立测试硬预算/节流/异常/嵌套/只读，独立review。部署启动与存档hash一致仅启动证据，不替代受伤/补员场景。
