# Issue #234 — 盾卫随旗与店匠维修

本轮代码范围：两金币举旗带同侧一名盾卫到长矛兵前方；盾牌上限从4提高至40；未碎盾卫安全后回店，由店内铁匠免费花时间修补。40耐久、6游戏秒安全、8游戏秒到店工时为首轮候选参数。当前没有安装新DLL，也没有以宿主测试代替游戏实测。

## 状态责任与兼容

- `HeavyShieldRuntime` 仍独占移动、朝向与动作。Banner只读取原生队形位置，向外偏0.4后限制最终目标；不写队形数组、不启用原生Archer AI。每次激活只选同侧一名，失员不递补，另一侧留守。
- Repair只有一名实际维修者；其他排队者守位。到店才累计工时；暂停/保存不计时，威胁、离店、撤收或迁址取消当次工时。使用现有店匠动画，不招募建墙工人、不新增工具/付款账本。
- 完成入口同时核对当前职业、原生生命、商店、原耐久和当前工时证明。policy与持久claim在无回调的同步段相邻提交；普通`UpdateCombatState`仍拒绝耐久上升。视觉更新后置，不会因显示失败重做维修。
- schema升级为v4，原生键仍为`KEM.HeavyShield.Campaigns.v1`。v1上限3，v2/v3上限4，先按旧格式验证，再按比例向上取整到40；v4重复读取不再换算。原有pending/unknown、权益、receipt、native ID与指纹保留，碎盾不复活。
- 指纹引入版本固定为3，独立于当前版本4；v3/v4继续要求唯一合法`hashKind`。旧版本Mod不认识v4格式，未来安装/回退必须保留对应存档备份，不能仅换回旧DLL就宣称兼容。

## 当前2.4依据与修正

当前Mac输入为IL2CPP 2.4.0 / Unity6000.0.61f1；GameAssembly universal SHA256 `738fb98871dd6e2136474325ea3f7f4f81f2094873a6bc88f7a942d268660b1a`。原生方法实现依据当前ARM64字节，interop只用于类型和签名。

- 已核`Player.ActivateFormation`和`Formation.OnDisable`不是折叠到其它CSharp方法的共享短入口。原生`GetFormationPosition`返回世界位置；`RestrictPosition`限制最终候选点。新增两个观察者是`HeavyShieldBanner+ActivateObserver`与`HeavyShieldBanner+DisableObserver`；原有六个盾卫战斗/退职前置保留。Android显式注册需独立接入这些观察者，不能以PC的PatchAll代替。
- 原生Scanner只有12个collider容量，`GetAll`返回有效数量，数组尾部会残留。当前控制代码只读取有效前缀；这也修正了旧目标选择/盾击可能读取尾部对象的问题。维修另核当次观察者、双向几何、全通筛选、未饱和及刷新一致性；不明时等待，不加全场扫描。
- 安全范围是原生Enemies层的当前局部矩形与最近正数伤害请求；不宣称扫描器覆盖飞行弹丸、落石或所有伤害源。提交前再强制刷新同一局部scanner。
- 首轮独审发现并修复了新context首帧误清已捕获旗令，以及关闭功能清除未知维修结果的问题。Banner自行管理Session/战役/岛屿上下文；普通关闭不解除未知结果，明确的新权威Session或确证旧生命结束才结束旧工作范围。
- 复审进一步区分原生命证明与单独`ended`状态。观察缺口后的`Life=0/Last=0`不能解除未知结果；精确旧生命停用，或同root已观察到明确正数新生命，才允许清理旧的managed凭据，不写替代生命的原生字段。
