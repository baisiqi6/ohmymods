# 双店美术与复核边界

用户追加要求：原版商店有店主，双店也应有人。英雄驿站采用奇幻弓匠铺、兜帽弓匠；火铳铺采用西式木构枪店、围裙枪匠。店主为建筑图集内装饰，不占人口，不创建AI、碰撞或寻路。四帧仅改变店主局部，建筑帧间保持；停顿为2000/500/1000/500毫秒，游戏暂停时Time.time不推进。

原始生成、授权本地像素整理、图集、预览和校验在 `artifacts/shops/20260917`。图集512×80，单帧128×80，PPU32，pivot(64,2)，不透明底边y77。二值alpha，64色；英雄占位旗仍为原有独立资源；火枪商品仍用原有实际库存实例。仅替换HeroShop.png、MusketeerShop.png，角色及枪弹资源保持。

独立reviewer只读检查预览和manifest：没有明显裁切或地面基线异常。Operator另按代码PPU、pivot与位置合成三枪库存/两英雄占位旗静态示意（shops-stock-composition.png）；旗帜位于两侧木板前且不遮店主，三枪处于店主上方。示意未计原生浮动、父变换或真实材质深度，游戏内最终叠加、颜色和动作观感尚未实测。

性能与掉落边界独立复核已通过：购买回调只用缓存，不进行LoadAll；缓存指针类型一致，支付前验证原生池。撤掉Character.DropItem的Nullable桥接，复用Droppable.Drop明确来源参数，不能读取可能残留的dropper字段。此为新增修复切片复核，不代替旧任务未完成的火铳职业附加档完整终审。

防守初版复核发现三问题：转职标记晚于原生分配、3秒缓存漏新普通弓手占位、缺墙时仍有原生守位回退。正在补正后重新复核。骑士持久化稳定context/epoch实现仍在端到端回归，不能把worker报告或纯函数通过当成实机恢复。
