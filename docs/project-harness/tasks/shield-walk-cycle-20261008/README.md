# Issue182 — 宝石盾卫背盾行走步态

用户观察到行走脚步怪异，要求修复并实装。追踪 Issue
[#182](https://github.com/baisiqi6/ohmymods/issues/182)。基线
`2df52f38910f44fdbbd2670fc27e687100853222`；本轮只替换 IL2CPP 两份盾卫图集的
back_walk 六帧 × 四档磨损，其他每图488格（485有效格、3padding）逐RGBA相同。

## 修复位置与交付

原素材六帧的腿/靴未充分形成可读的交替接地、抬脚与回摆。现有选序列、9fps时钟、
PPU/pivot和角色移动逻辑仍应负责原职责，错误产生于源帧，不需要运行时重绘、调速或扫描。
修正原分辨率腿部素材并保持脸、上身、手与完整盾形；粗像素仍保持各原帧28或29行的
像素支撑线，高清保持43行。没有修改产品C#、存档、购买、身份、战斗、对象池或网络。

中间版本遭独审拒绝：只移靴而留原银胫；腿映射末端偏移造成独立靴岛；固定盾行边界
漏第六帧盾边；旧镜像裁切预览漏腿。最终纠正腿链端点、逐帧盾轮廓及整格镜像预览。
粗像素一帧还出现从盾下取出被遮断靴件的碎块；改用完整接地源靴件并排除取件碎片，
没有用桥线补洞。原始中间稿和实际模型/进程证据保留本地任务目录。

交付为48个审核过的完整native帧、明确输出目录的简单打包器、独立像素回归与两图集。
制作期复杂行采样不进入游戏或产品算法；后续美术修改可直接编辑native帧再打包。

独立像素回归通过；拒绝稿R2按同检查失败，能抓断靴与盾边反例；R4还漏两枚暗盾边，

回归同样检出R4这两处缺口。未把露出的银胫暗边误锁成盾。
native打包重建与两产品PNG逐文件hash相同。既有真实PNG记录式Unity资源加载/切片/
采样/缓存及故障保护测试通过；Mac ARM实际interop离线构建0警告0错误，禁用部署。
